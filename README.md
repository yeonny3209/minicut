# MiniCut

브라우저에서 바로 쓰는 단일 파일 영상 편집기.
`index.html` 하나가 전부입니다. 설치도, 빌드도, 서버도 없습니다.

영상 파일은 `URL.createObjectURL`로만 읽고 **네트워크로 전송하지 않습니다.**
코드에 `fetch`나 `XMLHttpRequest`가 없습니다.

## 쓰는 법

[`index.html`](index.html)을 내려받아 Chrome 또는 Edge에서 엽니다. 끝입니다.

## 기능

**컷 편집** — 여러 영상 이어붙이기, 재생헤드 분할, 트림, 순서 변경, 삭제, 속도 0.25~4배
**자막** — 구간별 텍스트, 폰트 크기·색·외곽선·배경 박스·위치·정렬, 줄바꿈, SRT 내보내기
**색보정** — 밝기, 대비, 채도, 색온도, 비네트 (영상 전체에 적용)
**효과** — 페이드 인/아웃, 흑백, 세피아, 블러, 켄번즈 줌, 셰이크 (클립별로 중복 적용)
**내보내기** — 720p / 1080p / 원본 해상도, WebM (VP9 + Opus)

### 단축키

| 키 | 동작 | 키 | 동작 |
|---|---|---|---|
| `Space` | 재생 / 정지 | `←` `→` | 1프레임 이동 |
| `S` | 재생헤드에서 분할 | `Shift` + `←` `→` | 1초 이동 |
| `T` | 자막 추가 | `Ctrl` + `Z` | 실행취소 |
| `Delete` | 선택 항목 삭제 | `Ctrl` + `Shift` + `Z` | 다시실행 |

타임라인에서 `Ctrl` + 휠로 확대/축소할 수 있습니다.

## 설계 메모

**렌더링은 캔버스 한 장.** `<video>`를 숨겨 두고 매 프레임 캔버스에 그리면서 `ctx.filter`로
색보정을, 그 위에 효과와 자막을 겹칩니다. 프리뷰와 내보내기가 `renderFrame()` **하나만**
호출하므로 "보이는 대로 나온다"가 보장됩니다.

**재생 중에는 video가 기준 시계.** 재생헤드를 벽시계(rAF의 경과시간)로 굴리면 디코드 지연이나
탭 스로틀링 때문에 반드시 영상과 어긋나고, 그걸 매 프레임 시킹으로 메우다 보면 `readyState`가
떨어져 화면이 검게 깜빡입니다. 그래서 `video.currentTime`을 기준으로 삼고 재생헤드를 거기에
맞춥니다. 재생 중 시킹이 아예 필요 없어집니다.

**오디오는 Web Audio로 한 번 합칩니다.** 내보내는 중에 클립이 바뀌어도 MediaRecorder에 물린
오디오 트랙은 교체할 수 없어서, 모든 `<video>`를 하나의 믹스 노드로 모아 고정된 트랙 하나를
만듭니다.

**상태는 순수 JSON 하나.** `{clips, subtitles, adjustments, sources}`. 실행취소는 이 객체의
스냅샷 스택(최대 50개)으로 끝납니다.

## 제약

- **내보내기는 영상 길이만큼 실시간으로 걸립니다.** 화면을 `MediaRecorder`로 캡처하는 방식의
  구조적 한계입니다. 진행 중에는 창을 가리거나 최소화하면 안 됩니다 (가려지면 캔버스가 갱신되지
  않아, 깨진 파일을 내놓는 대신 중단하고 알려 줍니다).
- **내보내기는 Chrome / Edge 전용입니다.** Safari는 MediaRecorder의 WebM 출력을 지원하지 않아
  안내 메시지가 뜹니다. 편집과 프리뷰 자체는 동작합니다.
- **결과물 WebM을 MiniCut에 다시 불러오면 중간 지점 탐색이 깨집니다.** MediaRecorder가 만든
  WebM은 seek 인덱스(Cues)가 없고 키프레임이 드물어서, 파일 중간으로 seek하면 `currentTime`은
  정상 보고되지만 디코드된 프레임은 초반 키프레임에 머뭅니다. 일반 카메라·편집기 mp4는 키프레임이
  규칙적이라 문제없습니다. 재편집 왕복이 필요하면 WebCodecs 기반으로 인코딩 경로를 바꿔야 합니다.
- 멀티 비디오 트랙, 클립 간 전환 효과, 자동 음성인식 자막은 범위에 넣지 않았습니다.
